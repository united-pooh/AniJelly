# 电视直播与录像机移除说明

当前工作区删除电视直播、数字录像机（DVR）与通用频道插件扩展。这是功能及插件契约的不兼容变更；依赖电视接口的外部客户端/插件需要停止调用，服务端不提供替代电视入口。

## 删除范围

- `LiveTvController` 的 38 条 HTTP 声明及专用请求 DTO。
- `Jellyfin.LiveTv` 实现项目、专用测试项目、直播 Controller/Model 契约与元数据 provider；调谐器、节目指南、XMLTV/SchedulesDirect、定时与系列录制、录制通知和后台 host。
- 共享媒体库、搜索、DTO、用户权限与播放路径中只服务于电视/DVR 的分支，专用 XMLTV 包依赖。
- Web 中的电视/节目单/录制页面、管理配置、首页栏目、搜索与详情按钮、用户权限项、定时器通知和专用 API 请求。由第三份 [Web 功能移除补丁](../docker/jellyfin-web-no-livetv.patch)交付，前两份兼容与视觉补丁保持原顺序。
- 通用频道插件的 5 条 HTTP 声明、IChannel 相关接口/模型、缓存/图片/provider/刷新任务及 Web 入口和权限。

## 保留边界

- 普通电影、剧集、媒体库扫描和播放仍有对应接口；元数据、字幕和歌词插件不属于频道插件，继续保留。
- `ILiveStream`、`LiveStreams/Open` 和 `LiveStreams/Close` 是动态媒体源扩展的共享机制，名称含 live 不等于电视功能。
- 旧插件以 `Movie`、`MusicArtist` 等普通类型存储的条目，只要 `ChannelId` 非空且不是 `Guid.Empty`，也会从列表、按 ID 读取和艺人关联中排除；原始记录仍保留。
- 用户媒体文件、完成录制的视频文件、配置/缓存卷不删除。旧 `livetv` 配置文件和数据库历史记录不会被本轮清理主动擦除。
- 数据库历史迁移、保留编号的枚举与通用 `ProgramAudio` 数据类型继续存在，避免重排已有枚举含义；直播服务、任务和 UI 不再注册。外部直播或频道插件引用的已删类型不可继续使用。

## 验证

路由回归在删除前为 81 通过、1 预期失败；旧数据列表、直接按 ID 读取、同名艺人关联与升级迁移均有先失败后通过的保护。Release 全解决方案构建 0 警告、0 错误；最终测试汇总 4161 通过、2 项既有 DNS 环境失败、16 跳过。Web 215 项测试、类型与改动文件 lint 通过。详细结果见[手册核验记录](手册核验记录.md)。

已测镜像 `c015fd04` 已部署正式 8096，健康为 Healthy，服务器 ID/密钥/原两卷保持，管理员未初始化。生成 OpenAPI 为 251 路径 / 309 操作，两轮合计 96 条删除声明均缺席；普通动态开关流入口保留。临时实例验证 18 个计划任务无旧刷新任务，合成 H.264/AAC 短片扫描、HTTP Range、真实浏览器播放和暂停通过；这些结果不扩展为真实媒体或硬件转码已测。9 张截图与边界见[本轮验收记录](../.agent/visual/media-only-validation.md)，独立正式检查见[运行证据](../.agent/visual/media-only-runtime.json)。临时容器、两个测试卷、项目网络与私密 fixture 已清理；正式服务和原卷保持，见[清理证据](../.agent/visual/media-only-cleanup.json)。
