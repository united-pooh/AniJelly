# 动漫目录识别

本页对应 2026-10-13 的服务端源码修改。该修改尚未部署到当前运行容器。

## 分类规则

| 输入 | 服务端处理 |
| --- | --- |
| 剧集下的 `SP`、`SPs`、`特典`、`特别篇`、`特別篇` | 季目录解析为第 0 季，保留原有 `Specials` 规则；英文不区分大小写 |
| `第2季`、`第二季`、`第02期`、`第十二季` | 解析为对应季号；支持阿拉伯数字及零至九十九的常用汉字写法，含 `两`/`兩` |
| `作品 第二季 [1080p]` | 在父剧集目录名为“作品”时，去除父名称后识别第 2 季 |
| `第二季第1集`、`第二季 E01`、非法季数字 | 不当作季目录，不猜测第 1 季 |
| `NCOP`、`NCED` 目录中的视频 | 通过现有附加内容链路创建 `Video`，类型为 `ExtraType.Clip`，不创建剧集或特别篇条目 |
| `NCOP01.mkv`、`[作品][NCED02v2].mkv`、`作品 S00E01 - NCOP.mkv` | 文件中的明确 NCOP/NCED 标签优先分流为附加视频；放在正片季或特别篇目录里也不成为 `Episode` |
| 剧集或季内部的 `CDs` 目录 | 扫描时排除整个目录；不创建季或剧集，不删除文件，不改变音乐库及库根目录的处理 |
| 季号缺失或为负数 | 不默认采用第 1 季；TMDb 集元数据、剧照和 OMDb 季集元数据查询跳过 |

特别篇别名仅在季解析器允许特别篇别名时生效。NCOP/NCED 的英文标签不区分大小写，并识别编号及 `v2` 等版本后缀；不会把 `Syncope`、`NCOpening` 等包含相似字母的名称当作片头片尾。音频文件不会因 NCOP/NCED 文件名进入视频附加内容。

## 目录示例

```text
作品/
├── 第一季/
│   └── 作品 - 01.mkv
├── 第二季/
│   ├── 作品 - 01.mkv
│   ├── 作品 NCOP01.mkv
│   └── NCED/
│       └── 01.mkv
├── SPs/
│   ├── 作品 S00E01.mkv
│   └── 作品 S00E02 - NCOP.mkv
└── CDs/
    └── OST/
        └── 01.flac
```

此例中两个 `01.mkv` 分别属于第 1 季和第 2 季；`S00E01` 属于剧情特别篇；两个 NCOP 与 NCED 都属于附加视频，不能参与正片或特别篇的集数匹配。CDs 中的文件不进入番剧扫描。

## 刮削与已有数据

这套规则识别目录及文件标签，不识别视频内容。第 0 季第 1 集仍要求本地编号与所选元数据源一致，不能因为目录叫“特典”就保证远程标题正确。OVA/OAD 不在本轮自动归为第 0 季。

没有季目录、文件也没有季号的平铺剧集，会保留未知季号并跳过上述远程季集查询。需要明确 `S02E01`、季目录或本地元数据中的季号后才能按季集号刮削。已有明确季号在普通补全和重复解析中保持，不强制覆盖人工修正。

部署新服务端后才能应用这些规则。本轮不迁移数据库，也不批量撤销已有错误的季号、Provider ID、标题或图片；已有错配需逐项核对并安排重新扫描/刷新。
