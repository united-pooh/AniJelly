# 夜航客户端容器

夜航容器提供单文件界面，并将同源 `/api/` 请求代理到已有 AniJelly / Jellyfin。CRT 内使用真实首次设置和登录，媒体库、图片、收藏、播放流与观看进度均来自后端。它不再是可以离线独立登录、播放的演示页面，也不会创建第二个媒体服务器。

当前部署、媒体样本、截图、镜像标识与校验和以 [真实客户端验收](../../.agent/visual/night-real-validation.md)为准。本说明给出当前源码的启动方法，不把尚未归档的部署步骤写为已经通过。

## 连接已有服务器

[compose.yaml](compose.yaml)默认加入已有 Docker 网络 `anijelly_default`。[nginx.conf](nginx.conf)将 `/api/` 转发到同一网络内的 `http://jellyfin:8096/`，仅去掉 `/api` 前缀。启动前需要该网络存在，且后端在该网络内可用名称 `jellyfin` 访问。仅创建一个空网络不能代替启动后端。

已有服务器使用其他 Docker 网络名时，设置 `JELLYFIN_NETWORK`；后端仍须有 `jellyfin` 网络别名。若后端主机名或容器内端口不同，应调整 `nginx.conf` 的上游地址并重新构建。此容器不会更改后端配置或自动挂载媒体。

在本目录执行：

```sh
docker compose up -d --build --wait
```

打开 [夜航](http://127.0.0.1:18777/)。默认仅绑定本机 `127.0.0.1:18777`，不向局域网公开。更换本机端口和已有网络名的示例：

```sh
NIGHT_SIGNAL_PORT=18778 JELLYFIN_NETWORK=existing_jellyfin_network docker compose up -d --build --wait
```

`/#login` 与 `/#home` 对应登录和首页；详情、播放深链使用 `/#detail?id=条目ID`、`/#player?id=条目ID`，未经认证会回到登录页。旧的 `/夜航私人影院.html` 路径继续指向同一页面。

服务器未完成首次设置时，由用户填写首位管理员用户名与密码；已经设置过的服务器直接使用已有账号。客户端不会自动创建正式用户。库配置与媒体挂载仍在后端管理，当前用户没有可见媒体时首页显示空库，不产生演示海报。

## 会话、媒体与运行状态

令牌和当前用户存入本标签页的 `sessionStorage`，刷新时验证会话。退出先停止视频并报告进度，再请求服务器退出并清除客户端会话；401 会清理受保护页面。设备标识、静音和安静模式偏好使用浏览器 `localStorage`，不作为登录凭据。

收藏与播放进度存储在 Jellyfin 服务器。前端容器没有数据卷，也不缓存 NAS 视频；更换浏览器后重新登录同一账号，可读取服务器已保存的用户数据。本界面不提供离线播放、弹幕服务或 SyncPlay 控制。

查看状态、日志与停止：

```sh
docker compose ps
docker compose logs --tail=50 web
docker compose down
```

健康检查访问静态首页，只证明 nginx 正常响应；还需验证后端公开信息及实际认证、媒体请求。可先检查代理连接：

```sh
curl --fail http://127.0.0.1:18777/api/System/Info/Public
```

媒体图片与播放地址需要认证参数。API 代理关闭该路径的访问和错误日志，客户端使用 `no-referrer`；这不改变 Jellyfin 本身的日志配置。流响应不缓存、不缓冲到前端临时磁盘，后端转码能力和用户播放权限仍决定具体文件能否播放。

HEVC / HDR 播放会先检测浏览器能力，再协商直放、重封装或转码。Windows 上的 HDR 呈现还需要支持该格式的 Edge / Chrome、系统 HDR 设置和兼容显示器。播放器根据实际服务器会话显示是否复制视频或执行视频转码；“HDR 源”标签不代表已经验证端到端 HDR 显示。本轮没有 Windows 实体显示器的 HDR 成像验收。

## 更新客户端

HTML 内嵌界面样式、脚本、登录装饰图、字体和 hls.js。容器运行时不需要 Node、Python 或 CDN；这些内嵌资源不能替代后端服务。修改 `parts/` 后，在本目录运行测试、组装并重新构建：

```sh
npm ci
npm test
python3 build.py
docker compose up -d --build --wait
```

新增界面文字时，先按 [字体说明](assets/字体说明.md)重新生成子集与输入摘要，再执行 `build.py`。服务器动态标题不要求预先写入字体子集，缺少字形由系统字体回退。

Docker 构建上下文只包含 Dockerfile、nginx.conf 和生成的 HTML，源文件、截图及文档不会进入镜像。服务器以 UID/GID 101 运行，根文件系统只读，临时目录为 `/tmp` 内存盘。最终部署应比对容器返回 HTML 与本地构建的摘要，并在浏览器验证真实数据和视频，而不只检查健康状态。

## 导出和导入镜像

在完成目标版本构建及验收后导出：

```sh
mkdir -p dist
docker image save anijelly-night-signal:local | gzip > dist/night-signal-linux-arm64.tar.gz
```

将镜像包与 [compose.yaml](compose.yaml)复制到相同 CPU 架构的目标机器。目标机仍须运行可通过 `jellyfin:8096` 访问的后端，并准备相应 Docker 网络，再执行：

```sh
gunzip -c night-signal-linux-arm64.tar.gz | docker image load
docker compose up -d --no-build --wait
```

导入镜像无需重新下载基础镜像，但不能因此离线访问未同步的媒体服务器。镜像包针对构建时的 CPU 架构；ARM64 包不能当作原生 x86-64 镜像使用。架构不同时，将 Dockerfile、nginx.conf、HTML、.dockerignore 和 compose.yaml 一起复制并在目标机重新构建；基础镜像固定为多架构摘要。已有 `dist/` 包可能属于此前版本，使用前须核对 [真实客户端验收](../../.agent/visual/night-real-validation.md)记录的版本与校验和。

## 本机 Docker Desktop 连接

本机此前 Docker Desktop 默认代理 socket 曾发生 Compose 操作阻塞。若默认命令阻塞，可以在当前终端临时使用同一 Docker 引擎的 raw socket：

```sh
export DOCKER_HOST="unix://$HOME/Library/Containers/com.docker.docker/Data/docker.raw.sock"
docker compose ps
```

此路径仅适用于这台 macOS Docker Desktop，其他机器通常使用默认 Docker 连接。
